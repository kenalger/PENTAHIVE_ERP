Built the **GL posting engine / accounting bridge** for JKL ERP (Supabase `zpfkhcnxtiyojodtmepn`) on 2026-06-13. Bellion architected; Jinwoo built the core, Suho built the bridges.

**Architecture (server-side, presets-driven, trigger-fired):** source documents post via AFTER-INSERT/UPDATE triggers → SECURITY DEFINER handler → `fn_post_je(...)` → `journal_entries` + `journal_lines` (lines FK `acc_titles.id`). Account mapping is data-driven via the ported s2 **presets** layer (`acc_modules/acc_transactions/acc_preset_types/acc_preset_formulas/acc_presets/acc_preset_details`); `fn_resolve_account(txn_code, role)` returns the account id. Accounting logic is NOT in the Angular components.

**Migrations:** `gl_engine` + `gl_engine_lockdown` (Jinwoo: journal tables, presets schema, `fn_post_je`/`fn_resolve_account`/`fn_reverse_entry`/`is_posting_enabled`, GL views `v_journal_register`/`v_account_ledger`, GJ doc series, RLS). `gl_bridges` (Suho: module `JKL Operations`, txn codes VENDO/TOLL/WB/GRN/MILL/INVADJ, 18 presets, 5 handlers + 5 triggers, `fn_inventory_adjust` RPC).

**Key engine properties:** deferred CONSTRAINT TRIGGER enforces Σdebit=Σcredit (rolls back the source insert on imbalance); idempotent on `(source_table,source_id) WHERE entry_type='original'` (no double-post); immutable (BEFORE UPDATE/DELETE blocked — corrections via `fn_reverse_entry` only); EXECUTE on posting fns revoked from authenticated (handlers are SECURITY DEFINER); `gl_settings.posting_enabled` kill-switch that handlers check (reversals always work); GL SELECT gated by `can_access(uid,'general-ledger','view')`. Jinwoo also enabled RLS on `doc_counters` (fixed the long-standing advisory).

**What posts today (Phase 1, all verified balanced):** Vendo (Dr Cash/Cr Vendo Sales; expense reverse), Toll milling (Dr Cash/Cr Toll Revenue, VAT-exempt), Weighbridge (Dr Cash|AR / Cr Weighing Rev + Cr Output VAT 12%), GRN (Dr Inventory–Paddy/Cr GR-IR, GL value only via po_lines.unit_price — does NOT move inventory.on_hand), Milling on status→completed (WIP transformation), Inventory Adjust via `fn_inventory_adjust`.

**Open business decisions (Suho's documented assumptions — easily changed, they're preset/handler config):** weighbridge `price` treated VAT-INCLUSIVE (net=price/1.12); vendo NOT VAT-split; milling total_cost runs fully through paddy leg (conversion leg=0) and output split by physical qty. Beru to confirm. Also weighbridge fee-vs-grain-value semantics still open.

**O2C + P2P tails now BUILT (2026-06-13, Bellion plan → Jinwoo O2C + Suho P2P):** Sales Invoice (`sales_invoices`+new `sales_invoice_lines`, txn SINV: Dr AR / Cr Sales-Rice[exempt]+Sales-VATable+Output VAT, line-driven by `so_lines.vat`), Collection (`collections`, txn COLL: Dr Cash in Bank+CWT / Cr AR), Supplier Bill (new `supplier_invoices`+`supplier_invoice_lines`, txn SBILL: Dr GR/IR / Cr AP+WTP, from a posted GRN), Payment/CV (new `supplier_payments`, txn PAY: Dr AP / Cr Cash in Bank). `customers.ar_balance`/`ytd_sales` and `suppliers.ap_balance`(new col)/`ytd_purchases` now maintained by the handlers (idempotency-guarded: pre-SELECT existing JE before adjusting). AR/AP pages (`accounts-receivable`/`accounts-payable`) now real; entry points inline (SI from SO/Delivery, Collection from open SI, Bill from posted GRN, Payment from open Bill). Verified: GRN→Bill→Payment clears GR/IR & AP to 0.

**Still blocked/deferred (by design):** Delivery COGS at point of sale (deliveries header-only → needs delivery_lines + shared item key + costing method); perpetual inventory on_hand (SKU↔item_id mismatch G8); EWT remittance/Form 2307 generation (captured/posted but no 1601-EQ); partial-receipt EWT over-withholds (uses full-PO ewt); supplier-bill price variance.

**DCPR + BIR Compliance reporting modules BUILT (2026-06-14, Bellion plan → Jinwoo DCPR + Suho BIR).** Read-only reports over the live GL. **Critical security pattern:** GL tables are RLS-gated on `general-ledger`, so report RPCs are **SECURITY DEFINER, owned by a GL-reading role, self-gating on their own page code** (`if not can_access(auth.uid(),'dcpr'|'bir-compliance','view') then raise`) — else a report-only user gets silently EMPTY data. Supporting views are SECURITY INVOKER, read ONLY through the RPCs (locked from direct anon/authenticated select). **DCPR:** `rpc_dcpr(from,to)` + view `v_dcpr_lines`; per-cash-account (config `gl_settings.cash_account_ids` default {12,11}) opening→receipts→payments→closing with GL tie-out badge, transfer-netting rule, REVERSED badges; page `dcpr`, `src/app/dcpr/dcpr.ts`. **BIR:** 5 RPCs (`rpc_vat_summary`/`rpc_sales_register`/`rpc_purchase_register`/`rpc_cwt_received`/`rpc_ewt_withheld`), tie-outs to control accts (Output VAT 20, CWT 6, EWT payable 19); honest flags (missing-TIN on free-text WB/toll customers, missing-ATC, partial-receipt EWT, vendo zero-VAT caveat); page `bir-compliance`, `src/app/bir-compliance/bir-compliance.ts`. New cols: `gl_settings.vat_registered`, `collections.cwt_2307_received`/`cwt_2307_ref`, `supplier_invoices.atc`, `suppliers.default_atc`. Spec: `docs/dcpr-bir-compliance-spec.md`. Build note: bumped `angular.json` anyComponentStyle budget (help-center CSS ~25kB) to warn20/err32.

**Help Center SYNCED (2026-06-14):** flow-graph SI/Collection/Bill/Payment flipped COMING SOON→LIVE, GL convergence now 9 sources, module map AR/AP/DCPR/BIR=LIVE; Beru's accounting answers refreshed (selling posts, ar_balance maintained, DCPR/BIR live; honest caveats kept: COGS-at-sale deferred, 2307/e-filing manual, formatted BS/IS pending).

**Systemic Angular reactivity bug FOUND + FIXED app-wide (2026-06-14, Jinwoo; app is ZONELESS).** Two variants: (a) `computed()` over a plain `[(ngModel)]` object never recomputes → fixed by converting to methods (SO `customer()`, PO `supplier()`, bill `grossAmt/netPayable`, weighbridge preview, settings dirty-checks, COA modal title, milling toll/batch totals); (b) `async` handler assigning a plain form object after `await` with no signal write/`markForCheck()` → lines never render (AR `onSOChange`, GRN `onPOChange`, settings `loadProfile`). In a zoneless app a no-op `signal.set` does NOT trigger CD — use `markForCheck()`. Exhaustive audit done (all 47 components); zero sync instances remain. This bug had blocked SO-confirm + PO-save entirely.

**Tusk-verified live (2026-06-14):** full O2C (SO→Invoice→Collection) and P2P (GRN→Bill→Payment) chains post balanced JEs end-to-end; ar_balance/ap_balance round-trip to 0; GR/IR clears to 0; toll (post-fix, total live), vendo, weighbridge post correctly; DCPR ties to GL (green badges); BIR VAT Summary + Sales Book tie out; Help Center graph shows the live nodes. **Credit-limit enforcement** now real: SO Confirm computes available = credit_limit − ar_balance and sets `credit_hold` if exceeded (0/null limit = unlimited).

**Treasury Check Voucher (CV) + DCP built (2026-06-14, Beru spec → Bellion plan → Jinwoo CV → Suho DCP → Cha UX).** **CV** (page `check-voucher` under Treasury): pays one OR many APVs (supplier bills) per check; `supplier_payments` reshaped into CV header (+`cash_account_id` NOT NULL → drives cash credit) + new `supplier_payment_allocations` (payment_id, supplier_invoice_id, amount_applied); `supplier_invoices.status` now open/partial/paid; `v_apv_remaining` view = single source of remaining (`net_payable − Σ posted allocations`); RPCs `rpc_post_cv`/`rpc_open_apvs`/`rpc_void_cv` (SECURITY DEFINER, one-supplier-per-CV, FOR UPDATE lock vs double-pay, per-bill Dr AP + one Cr cash_account, ap_balance maintained, void reverses). **Retired the old single-bill PAY trigger** (`fn_bridge_supplier_payment`); the Accounts Payable page is now read-only and its Pay button deep-links to the CV page (`?supplier=`). **Fixed a real mis-post bug:** PAY had hardcoded the cash credit to Cash in Bank(11) regardless of paid_from; CV now credits the chosen `cash_account_id`. **DCP** (Treasury "Cash Position" page, route `treasury`): read-only `rpc_dcp(as_of, from, to)` (SECURITY DEFINER, gated on `treasury` page code) + views `v_dcp_position`/`v_dcp_forward`; Section A snapshot (per cash account opening→in→out→closing + consolidated, GL tie-out badges), B closing-balance trend (SVG sparkline), C indicative forward projection (open APV remaining by due_date as outflows, open AR as inflows, bucketed, negative-runway flag). DCP vs DCPR: DCP = position/liquidity, DCPR = receipts/payments register. v1 = 2 cash buckets (Cash on Hand 12, Cash in Bank 11), NOT per-bank (COA has no per-bank sub-accounts — deferred). Spec: `docs/treasury-cv-dcp-spec.md`. NOT yet Tusk-verified live (money-path gate pending: multi-bill CV, partial, void, concurrency, DCP tie-outs).
